# C# / .NET engineering

A checkable rule catalog plus the exact commands that prove a change. Rule IDs (`CS-NNN`) exist so a
review can cite them. Each rule says why it exists; when the repository has its own documented
convention that conflicts, follow the repository and note the deviation.

Facts below were checked on 2026-10-29 against official sources listed in the pack's
`sources/csharp.md`. Re-check versions with `dotnet --list-sdks` and the NuGet MCP server
(`get_latest_package_version`) before pinning anything new.

Reference files (read when the task touches the area):

- `references/project-baseline.md`: `global.json`, `Directory.Build.props`,
  `Directory.Packages.props`, `.editorconfig`, `nuget.config` templates and analyzer setup.
- `references/test-commands.md`: VSTest vs MTP `dotnet test` syntax, filters, coverage, dumps,
  mutation testing, per-framework packages.
- `references/diagnostics.md`: async/concurrency pitfalls with fixes, `dotnet-counters`/`-trace`/
  `-dump` recipes, BenchmarkDotNet setup, binlogs, EF Core query diagnosis.

## 0. Orientation checklist (run before editing)

1. `cat global.json` (SDK pin, `rollForward`, `test.runner`) and `dotnet --version`.
2. Owning project: `TargetFramework(s)`, `Nullable`, `ImplicitUsings`, `IsPackable`, `PublishAot`,
   `IsAotCompatible`, `OutputType`, SDK (`Microsoft.NET.Sdk.Web`, `.Worker`, `.Razor`).
3. `Directory.Build.props`/`.targets` and `Directory.Packages.props` up the tree (they apply
   silently; a property in the `.csproj` may be overridden there).
4. Test framework and platform (`xunit.v3`, `MSTest`, `NUnit`, `TUnit`; `Microsoft.NET.Test.Sdk`
   means VSTest unless MTP is configured).
5. Formatter in use: `dotnet format` with `.editorconfig` (default) or CSharpier (`.csharpierrc*`,
   `csharpier` in `.config/dotnet-tools.json`).

## 1. Language and type design

- **CS-001 Nullable on, warnings fatal.** `<Nullable>enable</Nullable>` and
  `<WarningsAsErrors>nullable</WarningsAsErrors>`. Null-forgiving `!` only with a justifying comment.
  Why: nullable warnings are the compiler finding real null dereferences for free.
- **CS-002 Language version follows the TFM.** C# 14 on `net10.0`, C# 15 on `net11.0`. No
  `preview`/`latest` `LangVersion` in shipping code; preview syntax changes between RCs.
- **CS-003 Least exposure.** `internal` by default, `sealed` unless designed for inheritance
  (CA1852), `private` fields, `readonly` where possible. Public surface is a contract you must
  version.
- **CS-004 Records for data.** `record class` for DTOs/messages/events; `readonly record struct`
  for small value objects such as `OrderId(Guid Value)`; no implicit conversions from primitives,
  so IDs cannot be mixed up silently.
- **CS-005 Exhaustive switches.** Switch expressions over enums/closed hierarchies have no blanket
  `_ =>` arm unless the domain truly has an "other" case; CS8509/CS8524 then flag new members. On
  `net11.0` use `closed` classes or `union` types for closed result sets.
- **CS-006 C# 14 idioms (net10.0).** `field` keyword instead of a hand-written backing field for
  validated properties; `extension(...)` blocks for extension properties/static members;
  null-conditional assignment `x?.Prop = v`; `nameof(List<>)`; collection expressions `[]`.
- **CS-007 Source generators over reflection.** `JsonSerializerContext` for System.Text.Json,
  `[GeneratedRegex]`, `[LoggerMessage]`, `[OptionsValidator]`,
  `<EnableConfigurationBindingGenerator>true</EnableConfigurationBindingGenerator>`. Required for
  trimming/AOT and faster at startup.
- **CS-008 No hand edits to generated code** (`*.g.cs`, `// <auto-generated>`, `obj/`, EF model
  snapshots except through `dotnet ef`).
- **CS-009 Primary constructors carefully.** Primary-constructor parameters are mutable captures,
  not `readonly` fields. For services that must not reassign dependencies, assign them to
  `private readonly` fields or keep a conventional constructor.
- **CS-010 Strings.** Use `StringComparison.Ordinal`/`OrdinalIgnoreCase` for identifiers, keys,
  protocol tokens; culture-aware comparison only for user-visible text. Format invariantly
  (`CultureInfo.InvariantCulture`) for machine-readable output (CA1305).

## 2. Errors and contracts

- **CS-020 Expected outcomes are values.** Not-found/validation/conflict are returned (result type,
  `TypedResults` in endpoints, or a `union` on `net11.0`); exceptions signal bugs and infrastructure
  failures.
- **CS-021 Guard clauses.** `ArgumentNullException.ThrowIfNull`,
  `ArgumentException.ThrowIfNullOrWhiteSpace`, `ArgumentOutOfRangeException.ThrowIfNegative`/
  `ThrowIfGreaterThan`, `ObjectDisposedException.ThrowIf` at public entry points.
- **CS-022 Preserve stacks.** `throw;` to rethrow; wrap with the inner exception only when adding
  context. No `catch (Exception)` except at a boundary that logs once and translates.
- **CS-023 Problem details.** APIs use `AddProblemDetails()`, `AddExceptionHandler<T>()` with an
  `IExceptionHandler` plus `UseExceptionHandler()`, `TypedResults.Problem`/`ValidationProblem`. No exception messages or stack
  traces in non-Development responses.
- **CS-024 Hosted services.** `ExecuteAsync` handles per-iteration failures and honors the stopping
  token. Default `BackgroundServiceExceptionBehavior.StopHost` stops the app on an unhandled
  exception; on .NET 11 `RunAsync` rethrows it (non-zero exit).
- **CS-025 Options validated at startup.** `services.AddOptions<T>().BindConfiguration("Section")
  .ValidateDataAnnotations().ValidateOnStart()` (or a source-generated `[OptionsValidator]`), so
  bad configuration fails the deploy instead of the first request.

## 3. Async, concurrency, DI lifetimes

- **CS-030 No sync-over-async.** No `.Result`/`.Wait()`/`.GetAwaiter().GetResult()` on incomplete
  tasks. Enforce with Microsoft.VisualStudio.Threading.Analyzers (VSTHRD002) as errors.
- **CS-031 Cancellation end to end.** Every I/O method takes `CancellationToken ct` (last
  parameter, `= default` only on public library APIs) and forwards it (CA2016).
- **CS-032 No `async void`, no fire-and-forget.** Background work goes through `Channel<T>` +
  `BackgroundService`, or an existing job system.
- **CS-033 Task hygiene.** `ValueTask` awaited once; `TaskCompletionSource` with
  `RunContinuationsAsynchronously`; timeout CTS disposed; `ConfigureAwait(false)` in libraries
  (CA2007 enabled for library projects only); `await using` for `IAsyncDisposable`.
- **CS-034 Eliding async.** Return a `Task` directly only from trivial pass-through overloads. If
  the method has `using`, `try`, or more than one statement, keep `async`/`await`; eliding there
  disposes too early or changes where exceptions surface.
- **CS-035 Shared state.** Prefer immutability, then `System.Collections.Concurrent`, then
  `Channel<T>`, then locks. Async mutual exclusion is `SemaphoreSlim.WaitAsync` in `try/finally`;
  synchronous is `System.Threading.Lock`. `ConcurrentDictionary.GetOrAdd` factories may run more
  than once; wrap expensive values in `Lazy<T>`.
- **CS-036 Bounded parallelism.** `Parallel.ForEachAsync` with `MaxDegreeOfParallelism`, or
  `Task.WhenAll` over a bounded batch; never unbounded `Select(async ...)` against a database or
  remote API.
- **CS-037 HttpContext.** Never stored in fields, captured by background tasks, or accessed from
  parallel tasks; it is not thread-safe and is recycled after the request ends.
- **CS-038 DI lifetimes.** Singletons depend only on singletons; `ValidateScopes` and
  `ValidateOnBuild` stay on in tests (`WebApplicationFactory` uses Development by default).
  `DbContext` is scoped; parallel work uses `IDbContextFactory<T>`.
- **CS-039 Time.** Inject `TimeProvider`; test with `FakeTimeProvider`
  (Microsoft.Extensions.TimeProvider.Testing). Use `PeriodicTimer` for loops.
- **CS-040 Ownership and disposal.** Whoever creates an `IDisposable` disposes it (`using`/
  `await using`); DI-created services are disposed by the container, so never dispose an injected
  dependency. Use `leaveOpen: true` overloads instead of leaking wrappers. Flush writers
  (`await writer.FlushAsync(ct)`) before disposing so async I/O is not forced synchronous.
- **CS-041 HttpClient.** Created by `IHttpClientFactory` (see CS-065) or a long-lived static
  `SocketsHttpHandler` with `PooledConnectionLifetime`; never `new HttpClient()` per call.

## 4. Data access (EF Core 10)

- **CS-050** Read paths: `AsNoTracking()` + `Select` projection to DTOs.
- **CS-051** No N+1: `Include`/`ThenInclude` (with `AsSplitQuery()` for multiple collections) or
  projection; assert query count or SQL in an integration test when it matters.
- **CS-052** Set-based writes: `ExecuteUpdateAsync`/`ExecuteDeleteAsync`.
- **CS-053** SQL safety: LINQ, `FromSql($"...")`/`ExecuteSql($"...")` interpolation (parameterized);
  `FromSqlRaw` only with explicit `DbParameter`s.
- **CS-054** Migrations: `dotnet ef migrations add <Name>`; review `dotnet ef migrations script
  --idempotent`; apply via a deploy step or migration bundle, not concurrently from N app
  instances at startup.
- **CS-055** Resilience: enable the provider's retrying execution strategy (for example
  `EnableRetryOnFailure()` on SQL Server) and wrap user-initiated transactions in
  `CreateExecutionStrategy().ExecuteAsync(...)`.
- **CS-056** Integration tests hit a real engine through Testcontainers, not the InMemory provider,
  whose semantics (no transactions, no relational constraints) hide real bugs.

## 5. ASP.NET Core (10)

- **CS-060** Minimal APIs with `TypedResults` (typed OpenAPI metadata, testable), grouped with
  `MapGroup`; controllers where the codebase already uses them.
- **CS-061** Validation: `builder.Services.AddValidation()` (DataAnnotations on parameters and
  bodies, 400 problem details on failure). It does not reject unknown JSON members; set
  `UnmappedMemberHandling.Disallow` where that matters.
- **CS-062** OpenAPI: `AddOpenApi()`/`MapOpenApi()` (Microsoft.AspNetCore.OpenApi) emits OpenAPI
  3.1 by default in .NET 10. On .NET 11, direct use of `Microsoft.OpenApi` types needs the v3
  migration.
- **CS-063** AuthZ deny-by-default: `builder.Services.AddAuthorizationBuilder()
  .SetFallbackPolicy(new AuthorizationPolicyBuilder().RequireAuthenticatedUser().Build())`.
- **CS-064** Rate limiting (`AddRateLimiter` + `RequireRateLimiting`), explicit CORS origins,
  HTTPS redirection + HSTS outside Development, antiforgery for form posts.
- **CS-065** Outbound HTTP: typed clients via `AddHttpClient<T>()` +
  `AddStandardResilienceHandler()`; set `BaseAddress` and a timeout; never forward user-controlled
  URLs without an allow-list (SSRF).
- **CS-066** Observability: `ILogger<T>` with `[LoggerMessage]`, structured properties (no string
  interpolation in log calls; CA2254), OpenTelemetry traces/metrics/logs (Aspire service defaults
  do this), health checks on `/health` with readiness vs liveness split.
- **CS-067** Caching: `HybridCache` for cache-aside with stampede protection; output caching for
  whole responses.

## 6. Performance (measure first)

- **CS-070** Claims need numbers: BenchmarkDotNet (Release, `[MemoryDiagnoser]`, compare to a
  baseline job) or production counters/traces. See `references/diagnostics.md`.
- **CS-071** Hot-path allocation tools: `Span<T>`/`AsSpan` slicing, `ArrayPool<T>` (return in
  `finally`), `string.Create`, `StringBuilder` for loops, `FrozenDictionary` as a candidate for read-mostly maps,
  `TryGetValue` instead of `ContainsKey` + indexer, no LINQ in measured hot loops. These are candidates, not
  guaranteed wins: keep each only when a BenchmarkDotNet comparison against the baseline shows it.
- **CS-072** Regex: `[GeneratedRegex]` for static patterns; untrusted input gets a match timeout or
  `RegexOptions.NonBacktracking`; no nested quantifiers like `(\w+)+`.
- **CS-073** `stackalloc` only for small constant sizes, outside loops; above ~1 KB use the pool.
- **CS-074** Native AOT / trimming: `PublishAot` for apps, `IsAotCompatible` for libraries; build
  must have zero IL2xxx/IL3xxx warnings; no `Assembly.Load`, `Type.GetType(string)`, or
  reflection-based serializers on that path.
- **CS-075** Server GC is the ASP.NET Core default; containers should set memory limits so the GC
  sizes heaps correctly. Investigate GC with `dotnet-counters` before tuning settings.

## 7. Security and supply chain

- **CS-080** No secrets in source or `appsettings*.json`; `dotnet user-secrets` locally,
  environment/Key Vault in production.
- **CS-081** Crypto primitives: `RandomNumberGenerator.GetBytes`/`GetHexString` for tokens,
  `CryptographicOperations.FixedTimeEquals` for secret comparison, Identity `PasswordHasher<T>`,
  Data Protection API for reversible protection. No MD5/SHA1 for security purposes (CA5351/CA5350).
- **CS-082** Deserialization: System.Text.Json without polymorphic type-name handling from
  untrusted input; no `BinaryFormatter` (removed in .NET 9); `XmlReaderSettings.DtdProcessing =
  Prohibit`.
- **CS-083** Paths: `Path.GetFullPath(Path.Combine(root, input))` must start with the normalized
  root; reject otherwise.
- **CS-084** Logging: never log secrets, tokens, or full request bodies; redact with
  Microsoft.Extensions.Compliance.Redaction where PII is logged.
- **CS-085** NuGet Audit: on by default; `NuGetAuditMode` is `all` (transitive) for `net10.0`+.
  CI treats NU1901-NU1904 as errors. Fix with `dotnet package update --vulnerable`.
- **CS-086** Package sources: one `nuget.config` with `<clear/>` + explicit sources and
  `packageSourceMapping` when more than one feed exists (prevents dependency confusion). The .NET 11
  SDK can set a `minPublishAgeHours` cooldown per source from the CLI
  (`dotnet nuget add source ... --min-publish-age-hours 24`) so brand-new versions are not picked up
  immediately.
- **CS-087** Applications commit `packages.lock.json` (`RestorePackagesWithLockFile`) and CI
  restores with `--locked-mode`.
- **CS-088** Licenses: check before adding. FluentAssertions 8+ (Xceed, non-commercial community
  license), AutoMapper 15+ and MediatR 13+ (Lucky Penny commercial) need the user's agreement;
  open alternatives are AwesomeAssertions (Apache-2.0), Shouldly (BSD-3-Clause), explicit mapping
  or Mapster (MIT), plain handlers.

## 8. Build, packaging, repository layout

- **CS-090** `global.json` pins the SDK with `"rollForward": "latestFeature"`; `Directory.Build.props`
  holds shared properties; `Directory.Packages.props` holds versions (CPM). Templates in
  `references/project-baseline.md`.
- **CS-091** Use the CLI to change packages and references: `dotnet package add|update|remove|list`
  and `dotnet reference add` (noun-first forms are the .NET 10 standard).
- **CS-092** `.slnx` solution format for new repos; one solution format per repo.
- **CS-093** Analyzer baseline: `<AnalysisLevel>latest-recommended</AnalysisLevel>`,
  `<EnforceCodeStyleInBuild>true</EnforceCodeStyleInBuild>`, `TreatWarningsAsErrors` in CI, plus
  the repo's chosen third-party analyzers (Meziantou, Roslynator, Sonar, VS Threading). Suppress
  individual findings with a justification (`[SuppressMessage(..., Justification = "...")]` or a
  scoped `.editorconfig` entry), never project-wide `<NoWarn>` for real rules.
- **CS-094** Libraries: `GenerateDocumentationFile`, `PackageReadmeFile`, `PackageLicenseExpression`,
  SourceLink (on by default for SDK 8+ with GitHub/Azure DevOps remotes), PublicApiAnalyzers
  (`PublicAPI.Shipped.txt`/`Unshipped.txt`), multi-target only when consumers need it.
- **CS-095** CI: `ContinuousIntegrationBuild=true`; build once, test with `--no-build`, publish
  with `--no-build` where possible; cache `~/.nuget/packages` keyed on lock files.
- **CS-096** Containers: `dotnet publish -c Release /t:PublishContainer` (works for web, worker and
  console apps on SDK 10); run as non-root; prefer chiseled/distroless runtime images.
- **CS-097** Support windows: .NET 8 and .NET 9 end support on 2026-11-10; new work targets
  `net10.0` (LTS to 2028-11-14). Target `net11.0` only when the user accepts an RC/STS release.

## 9. Testing rules

- **CS-100** Test the behavior through public APIs; one behavior per test; names describe the
  behavior (`PlaceOrder_WhenStockIsInsufficient_ReturnsConflict`).
- **CS-101** Use the framework already in the solution; new solutions default to xUnit v3 on MTP
  (MSTest 4, NUnit 5 and TUnit are equally valid if the team prefers them).
- **CS-102** HTTP behavior: `WebApplicationFactory<Program>` (expose `Program` with
  `public partial class Program;` when needed); replace external dependencies at their boundary
  (HTTP message handler, `TimeProvider`, Testcontainers), not by adding interfaces everywhere.
- **CS-103** No `Thread.Sleep`/`Task.Delay` for synchronization in tests; await the condition or
  use `FakeTimeProvider`.
- **CS-104** Never skip, delete, or weaken a test to go green. A wrong test is fixed openly with
  the reason stated.
- **CS-105** Snapshot tests (Verify) for large serialized outputs; property-based tests (FsCheck,
  CsCheck) for parsers and invariants; mutation testing (Stryker.NET) for critical domain logic.

## 10. Gate commands

Run in this order; stop at the first failure and fix it. Exact VSTest/MTP variants are in
`references/test-commands.md`.

```bash
dotnet --version
dotnet restore --locked-mode                          # plain `dotnet restore` if no lock files
dotnet format --verify-no-changes --no-restore         # whitespace + style + analyzer fixes
dotnet csharpier check .                               # only if the repo uses CSharpier
dotnet build -c Release --no-restore -warnaserror
dotnet test -c Release --no-build                      # VSTest projects; SDK 8/9 (bridge args after --)
dotnet test --project <tests.csproj> -c Release --no-build   # native MTP (global.json test.runner);
                                                        # required for MTP v2 frameworks on SDK 10
dotnet package list --vulnerable --include-transitive
dotnet package list --outdated                         # informational
```

Pass criteria: every command exits 0; build prints `0 Warning(s)` and `0 Error(s)`; tests report
`failed: 0` (MTP summary) or `Failed: 0` (VSTest) with a non-zero total that is not lower than the baseline; the audit prints "has no vulnerable packages" for every project (the audit command itself exits 0 even
when it finds vulnerabilities, so read the text or grep for `> ` rows). Zero discovered tests is a failure.

Conditional gates:

| When | Command | Pass |
|---|---|---|
| Coverage of changed code | native MTP: `--coverage --coverage-output-format cobertura`; VSTest: `--collect "XPlat Code Coverage"`; then `dnx dotnet-reportgenerator-globaltool --yes -- -reports:"**/TestResults/**/*.cobertura.xml" -targetdir:artifacts/coverage -reporttypes:TextSummary` | changed files covered; no drop vs baseline |
| Hangs / deadlocks | VSTest `--blame-hang --blame-hang-timeout 5min`; MTP `--hangdump --hangdump-timeout 5min` | no dump produced |
| Suspected race | re-run the focused tests 20x in a loop that exits 1 on the first failure (`|| { echo "race on $i"; exit 1; }`, never `|| break`); analyze any dump with `dotnet-dump analyze` (`dumpasync`, `syncblk`, `clrstack -all`) | 20/20 green |
| AOT / trimming | `dotnet publish -c Release -r linux-x64 -p:PublishAot=true` | zero IL2xxx/IL3xxx |
| Performance claim | `dotnet run -c Release --project <bench> -- --filter '*' --memory` | numbers vs baseline in report |
| Critical domain logic | `dotnet tool restore && dotnet stryker --break-at 60 --since:main` (`--test-runner mtp` for MTP) | exit 0 and a mutation score printed; "unable to calculate a mutation score" = not run |
| Build mystery | `dotnet build -bl:artifacts/build.binlog`, inspect with the binlog MCP or MSBuild Structured Log Viewer | root cause named |

Native-code sanitizers (ASan/TSan) do not apply to managed code. For P/Invoke into native libraries,
sanitize the native side in its own build and keep the managed boundary covered by tests.

## 11. Review checklist (paste into a review)

- [ ] Nullable clean without new `!`/suppressions (CS-001)
- [ ] Async: no blocking waits, tokens forwarded, no async void (CS-030..033)
- [ ] Disposables disposed; HttpClient via factory (CS-040, CS-041, CS-065)
- [ ] DI lifetimes valid; no HttpContext capture (CS-037, CS-038)
- [ ] EF queries projected/no-tracking; no N+1; parameterized SQL (CS-050..053)
- [ ] AuthZ fallback policy intact; input validated; no secrets (CS-061, CS-063, CS-080)
- [ ] Packages added via CLI, CPM respected, licenses checked, audit clean (CS-085..091)
- [ ] Tests seen failing first; none skipped or weakened (CS-104)
- [ ] Gate output pasted (section 10)

## Addenda (orchestrator fixes from the blind score, 2026-10-29)

These close coverage gaps the blind scorer found. They are rules, not measured claims.
- **Blazor.** Choose the render mode deliberately (Static SSR, InteractiveServer, InteractiveWebAssembly,
  InteractiveAuto). With prerendering, `OnInitializedAsync` runs twice, so carry state across with
  `PersistentComponentState` instead of fetching twice. Components that hold resources implement
  `IAsyncDisposable`. Dispose `IJSObjectReference` handles. Never put secrets in WebAssembly code (it
  ships to the browser). Test components with bUnit.
- **Authentication.** `AddJwtBearer` keeps issuer, audience and lifetime validation on, with Authority and
  Audience from configuration; never disable validation, not even in development. Cookie auth uses
  `SecurePolicy = Always`, `HttpOnly`, and `SameSite = Lax` or `Strict`. Interactive login uses
  `AddOpenIdConnect`. Browser apps keep tokens out of `localStorage` (use the BFF pattern).
- **Library packaging.** Conditional gate: `dotnet pack -c Release --no-build -o artifacts/pkg`. Pass means
  a `.nupkg` plus a `.snupkg` (`<IncludeSymbols>true</IncludeSymbols><SymbolPackageFormat>snupkg</SymbolPackageFormat>`)
  and clean package validation (`<EnablePackageValidation>true</EnablePackageValidation>`). Publish from CI
  with nuget.org Trusted Publishing (OIDC) instead of a long-lived API key.
- **Aspire.** Keep orchestration in the AppHost only. Every service calls `AddServiceDefaults()` and
  `MapDefaultEndpoints()`. Test the composed app with `Aspire.Hosting.Testing`. Check the current Aspire
  CLI version in the docs before pinning it.
- **Runtime and interop.** Server GC with DATAS (dynamic adaptation, on by default with Server GC since
  .NET 9) suits containers; `GCDynamicAdaptationMode=0` turns it off if measurements say so. Use
  `[LibraryImport]` (source-generated) over `[DllImport]` for AOT-safe P/Invoke. Dapper and raw ADO.NET
  always pass parameters objects, never interpolated SQL.
- **Template hygiene.** In BenchmarkDotNet projects, keep `Program` in its own `Program.cs` (MA0048,
  one type per file) or relax MA0048 for `bench/**`. Run `dotnet tool restore` before `dotnet csharpier check`
  and `dotnet stryker`.
- **NuGet MCP.** Its tools need an absolute `solutionDirectory`. `get_latest_package_version` also needs
  `includePrerelease` (false unless asked). Without them it returns a bare "An error occurred invoking".
